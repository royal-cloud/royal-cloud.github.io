Data practices

Privacy Policy

Last updated: 14 October 2026. This policy covers the personal YouTube Live Archiver maintained by the GitHub account royal-cloud.

Information the app uses

The app processes the YouTube URL chosen by the user, the video's title and identifier, stream availability information, and the audio/video recording. To save files, it uses Google OAuth access and refresh tokens and information about archive files it creates in Google Drive.

Google permissions and purpose

The sole Google API scope requested is https://www.googleapis.com/auth/drive.file. Google access is used to create an archive folder, upload recordings and safety parts, verify uploaded file checksums, check available storage where supported, and remove temporary test files or safety parts after a verified final upload.

The app does not request access to Gmail, contacts, or the user's complete Drive. Information received through Google APIs is used only to provide this archiving function. It is not sold, used for advertising, used to build user profiles, or used to train AI models. Use of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements.

Storage and access

The OAuth refresh token is stored encrypted in the maintainer's private GitHub repository. The separate encryption key, Google client credentials, and any optional YouTube cookies are stored in GitHub Actions Secrets. Temporary authorization files and recording data are processed on the GitHub-hosted runner. Credential files are removed when the job completes; interruption may prevent cleanup before the runner is discarded.

Recordings are stored in the Google Drive account the user authorizes. The maintainer and administrators of the private repository can control the workflows and secrets. Google and GitHub process the information needed to provide their respective services. The public information website does not receive OAuth tokens or recordings and does not provide a login form.

Retention and deletion

Final recordings remain in the user's Drive until the user deletes them. Safety parts are normally removed after a final upload has been verified, unless the user chooses to keep them or a failure requires preserving them. Workflow logs can contain video titles, URLs, and operational results and follow the repository's Actions log-retention settings. Stored authorization remains until it is removed or replaced; Google may expire or revoke it.

Revoke access

The user can revoke this app's access in Google Account connections. Revocation stops future authorized Drive operations. It does not delete existing recordings. The user can delete those files in Drive, and remove the encrypted authorization from the private repository.

Optional YouTube cookies

If YouTube requires authenticated access, the user may supply cookies through a private GitHub Actions Secret. They are used only to access the selected YouTube content and are written temporarily on the runner. Cookies should not be placed in public files or issues.

This information website

This site has no application analytics, advertising, or application cookies. GitHub Pages serves it and may process request metadata under GitHub's privacy statement.

Questions and changes

Questions about this app can be raised through the public information repository. Do not include credentials, cookies, private recording links, or other sensitive information in a public issue. Changes to this policy will be published here with an updated date.
